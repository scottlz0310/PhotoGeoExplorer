# ✔️全体プロトコル

まず最初にこれをエージェントに与えます👇

```text
あなたはC#/.NET WinUI3のコードベースを扱うシニアアーキテクトです。

このタスクは以下のフェーズで進行します：

1. 理想アーキテクチャ定義（コード参照禁止）
2. リポジトリ監査（境界違反検出）
3. 是正計画（ISSUE設計）
4. 段階的リファクタリング（小さな単位）
5. テスト追加と検証

## 最重要原則
- 目的は「カバレッジ向上」ではなく「テスト可能性の向上」
- 変更は常に小さく、安全に行う
- 常にビルド可能な状態を維持する
- 推測禁止、コード根拠ベースで判断する
```

---

# ✔️Phase 1：理想定義（コード見せない）

```text
コードベースは一切参照せず、理想的なMVVMアーキテクチャを定義してください。

## 目的
- テスタビリティ最大化
- UI非依存なViewModel

## 定義内容

### 1. レイヤー責務
- View / ViewModel / Model / Service の責務

### 2. 依存ルール（最重要）
- 許可される依存
- 禁止される依存
- 依存方向

### 3. ViewModel制約
- 使用可能なAPI
- 禁止事項（UI参照、Dispatcher等）

### 4. テスタビリティ要件
- モック可能性
- 外部依存の扱い
- 状態の観測可能性

### 5. 非同期設計
- async/awaitのルール
- fire-and-forget禁止
- 例外伝播

### 6. DI方針
- インターフェース導入基準

## 出力形式
- 明文化されたルールセット
- Yes/Noで判定可能なチェックリスト

## 制約
- 曖昧表現禁止
- 実装ではなくルールに集中
```

---

# ✔️Phase 2：リポジトリ監査

```text
Phase1で定義したルールに基づき、リポジトリ全体を監査してください。

## 検出対象

### 1. MVVM境界違反
- ViewModel → UI依存
- View → ロジック保持
- Model → インフラ依存

### 2. テスト不能要因
- newによる直接依存
- static依存
- hidden dependency
- 非同期不整合

### 3. 構造的問題
- Service不在/過密
- 責務重複
- 疑似MVVM

## 出力

### A. サマリ
- 違反件数（カテゴリ別）
- 問題の大きい領域Top5

### B. 詳細リスト
- ファイル
- 違反内容
- 根拠コード
- 影響範囲
- 修正難易度

### C. スコアリング
- 各ViewModelのテスタビリティスコア（0〜100）

## 制約
- 網羅性最優先
- 推測禁止
- コード変更禁止
```

---

# ✔️Phase 3：是正計画（ISSUE生成）

```text
監査結果をもとに、段階的リファクタリング計画をGitHub Issueとして設計してください。

## 要求
- 親ISSUE（EPIC）を作成
- サブISSUEに分割
- 各ISSUEは1〜2日で完了可能

## Issue分類
1. UI依存除去
2. DI化（依存抽象化）
3. 非同期整理
4. Service分離
5. テスト追加

## 各ISSUEに含める
- 背景
- 対象ファイル
- 具体的変更内容
- Definition of Done
- テスト戦略
- リスク
- 依存ISSUE

## 制約
- 1ISSUEあたり最大5ファイル変更
- 常にビルド可能
- 横断変更は分割

## 完了条件（必須）
- ビルド成功
- 既存機能維持
- テスト可能状態
```

---

# ✔️Phase 4：段階的リファクタリング（実装）

```text
指定されたISSUEを1つだけ実装してください。

## ルール
- 指定ファイル以外変更禁止
- 完全なコードを提示
- 差し替え可能であること

## 必須
- DI対応（コンストラクタインジェクション）
- 外部依存のインターフェース化
- UI依存除去

## 禁止
- static依存
- Service Locator
- UI API参照

## 出力
- 修正コード
- 変更理由
```

---

# ✔️Phase 5：テスト生成

```text
変更対象のViewModelに対して単体テストを作成してください。

## 条件
- UI非依存
- モック使用
- 正常系・異常系・境界値を網羅

## 出力
- テストコード（xUnit）
- テスト観点
```

---

# ✔️Phase 6：検証（品質ゲート）

```text
リファクタリング後のコードを検証してください。

## チェック項目
- ViewModelがUI非依存か
- モック可能か
- 非同期が安全か
- 責務分離が成立しているか

## 出力
- OK / NG
- NGの場合の修正案
```

# ✔️補助プロンプト（精度ブースト）

## テスト駆動リファクタリング

```text
まずテストを書こうとし、書けない理由を列挙してください。
その理由を解消するリファクタリングを提案してください。
```

👉 **最も実用的で精度が高い**

---

## 境界ルール適用

```text
以下のルールに違反している箇所のみを抽出してください。
```

👉 ノイズ削減

---

## 危険変更の分離

```text
リスクの高い変更は独立したISSUEとして分離してください。
```
