- [x] 前回と同じフォルダーを復元すると決定ボタンが無効になることを確認（ユーザー実機確認）
- [x] Windows App SDK の FolderPicker に移行し、WindowId と結果の Path を使用
- [x] 移動・コピー・開くの履歴を機能別の SettingsIdentifier に分離
- [x] 手動確認手順・CHANGELOG を更新
- [x] 開く・コピー・移動の3経路で、同じフォルダーを続けて確定できることを実機確認（非パッケージ起動、ユーザー確認）
- [x] キャンセル時にファイル操作・フォルダー遷移が行われないことを実機確認（開く: 非パッケージ・MSIX、移動・コピー: MSIX。2026-10-14）
- [x] MSIX 配布版で `SettingsIdentifier` による前回フォルダーの復元を確認 → **復元されない**（初期位置は3経路とも常にピクチャ。2026-10-14）。3経路の履歴分離は、復元されないため確認できない
- [x] Debug/x64・Release/x64 analyzer ビルド、単体テスト788件、format を確認

E2E は通常の実行ゲートにより14件スキップ。

非パッケージ起動では `SettingsIdentifier` による前回フォルダーの復元は確認できず、初期位置は常にピクチャ（`SuggestedStartFolder` に替えても同じ）。MSIX でも同じだったため（2026-10-14）、復元の扱いは [Issue #262](https://github.com/scottlz0310/PhotoGeoExplorer/issues/262) で判断する。現在表示中のフォルダーを初期候補にする UX の変更は含めない。

#262 で、開く・移動・コピーの前回確定フォルダーをアプリ側でアプリ実行中だけ記憶し（設定ファイルへは保存しない）、`SuggestedFolder` として渡すようにした。記憶が無い、またはフォルダーが存在しない場合は、いま表示しているフォルダー（存在しなければ存在する最も近い親フォルダー）、それも無ければピクチャから開く。
